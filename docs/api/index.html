Highlights API

A local HTTP service that turns a soccer broadcast into timestamped highlights. Scene cuts and object detection run on your machine. A rule filter drops the stretches with nothing going on, and a multimodal LLM labels what's left.

  • Base URL http://127.0.0.1:3000
  • JSON over HTTP
  • No auth, localhost only
  • TypeScript + Effect

How a job runs

Every job goes through seven stages. Each stage's output is cached under a key built from its inputs, its parameters and the model weights. A later job reuses every stage whose inputs haven't changed.

probehash and ffprobe the file
scenesTransNetV2 scene cuts
detectionsYOLO player, ball and referee counts
windowsrule filter (config C)
segments40 s clips, 5 s overlap
verdictsmultimodal LLM via OpenRouter
highlightsmerge overlaps, map to video time
runs on your machineruns on OpenRouter

Changing only the rule reruns windows and everything after it. Scene cuts and detections, the slow part, are reused, and so is any LLM answer for a clip with identical bytes.

Run it locally

Everything except the LLM call runs on your machine: the API server, its SQLite store, ffmpeg, and the CV worker that runs TransNetV2 and YOLO on the GPU or CPU.

    git clone https://github.com/giovanni1351/Tcc_analise_regras_cortes.git
cd Tcc_analise_regras_cortes
git checkout feat/design-video-analysis-api   # until PR #3 is merged
  2. Install dependencies 
    mise install            # Node 26.13.1 and pnpm 12.14.0
pnpm install
uv sync --frozen        # Python env for the CV worker: torch, ultralytics, transnetv2-pytorch

    The YOLO weights (best.pt) are in the repository root. The TransNetV2 weights come with the transnetv2-pytorch package. Both are hashed into the cache keys, so swapping either one reruns only the stages that use it.

  3. Try the API without a GPU or a key 
    TCC_DEV_FAKE_STAGES=true pnpm start serve

    Dev mode replaces probing and every pipeline stage with instant fakes. It's for building a client against the real contract. Any file works as a source.

  4. Run the real server 
    export OPENROUTER_API_KEY=sk-or-...   # used only for the verdicts stage
pnpm start serve                      # listens on 127.0.0.1:3000

    The server starts the CV worker on demand. It uses the GPU when torch.cuda.is_available(), and you can force a device with CV_DEVICE=cpu or CV_DEVICE=cuda. The default model is a free OpenRouter model, so jobs cost $0 unless you choose a paid model.

  5. Analyze a video 
    # any local file
pnpm start analyze /videos/match.mkv

# a SoccerNet half: league/season/game/half/resolution
TCC_SOCCERNET_ROOT=/data/soccernet \
  pnpm start analyze "soccernet:england_epl/2014-2015/2015-04-11 - 19-30 Burnley 0 - 1 Arsenal/2/224p"

pnpm start jobs              # list jobs and their state
pnpm start result <job-id>   # highlights once the job finishes

    SoccerNet halves resolve to <root>/<league>/<season>/<game>/<half>_<resolution>.mkv, the layout the official downloader writes.

  6. Check your setup 
    pnpm test        # unit and integration tests
pnpm typecheck
pnpm lint

# CV parity: the worker against the reference Python on a 60 s clip (needs CUDA)
TCC_CV_TEST_VIDEO=/data/soccernet/.../2_224p.mkv pnpm test apps/server/src/cv

    The parity test skips itself without CUDA or a test video.

Paid models are opt-in. The CLI refuses a paid model unless you pass it as an explicit argument, for example pnpm start analyze match.mkv google/gemini-3.1-flash-lite. With OPENROUTER_BUDGET_USD at its default of 0, the server refuses every paid call. For a hard ceiling, use a dedicated OpenRouter key with its own credit limit, at least $1.00 above what you plan to spend: OpenRouter won't run a video request below $1.00 of remaining credit.

Sources

A source is a video you register once. The server hashes and probes it. Two references to the same bytes share one media record, so they share every cached stage too.

// a file on disk
{ "_tag": "LocalFile", "path": "/videos/match.mkv" }

// a SoccerNet half, resolved under TCC_SOCCERNET_ROOT
{ "_tag": "SoccerNetHalf", "league": "england_epl", "season": "2014-2015",
  "game": "2015-04-11 - 19-30 Burnley 0 - 1 Arsenal", "half": 2, "resolution": "224p" }

A SoccerNet source tells the server which half it is, so its highlights carry half. For a local file, half is null.

Jobs and caching

A job is one source plus one spec. Creating a job is idempotent: the same source and spec return the existing job unless you pass force. Leave the spec out to get the defaults.

{
  "rule": { "_tag": "Zero", "short": 25, "zero": 0, "cluster": 1,
            "preceding": true, "use_zero": true, "before": 10, "after": 16 },
  "llm": { "model": "nvidia/nemotron-3.5-super-vl:free",
           "promptVersion": "benchmark-v1", "maxCostUsd": 0.1 },
  "clips": true,
  "segmentation": { "maxSec": 40, "overlapSec": 5 }
}
  • rule is the pre-LLM filter. The default is the thesis's config C, which keeps about two thirds of a half. Context is the other rule family.
  • llm.maxCostUsd caps this job's paid spend. The job stops as Partial before a call that would cross it.
  • clips keeps an MP4 for each highlight, served from /blobs.
  • segmentation sets the clip length sent to the LLM: maxSec between 10 and 120, and overlapSec under half of it. 40/5 was chosen by tuning; 20/4 scored lower.

Job states

Queued→Running→ Succeeded|Partial|Failed|Cancelled

Running carries the current stage and its progress. A single runner works through jobs one at a time. At startup, jobs left Running go back to Queued and skip every stage that already finished.

Partial means the job finished, but some segments got no answer. coverage says how many, and reason says why:

ReasonWhat happenedWhat to do
BudgetExceededThe next call would cross the job cap or the account budget.Raise the cap or budget, then resume.
FreeDailyLimitThe free model's daily quota ran out.Resume after retryAfterMs.
CreditExhaustedOpenRouter refused for lack of credit.Top up, then resume.
AmbiguousAttemptsA paid call was sent but its reply never arrived, so we can't know whether it was billed.Resume with retryAmbiguous: true to send it again on purpose.

coverage counts the segments: valid answers, invalid answers (well-formed replies that broke the schema or were cut off, which count as data), ambiguous, and notSent.

Paid calls and budget

A paid call can charge money and then fail before its reply reaches the database. So every attempt is written down before it's sent:

Reserved→Sent→ Answered|Failed|Ambiguous
  • Reserved: admission is checked, and a pessimistic cost is held, in one transaction.
  • Sent: recorded just before the request leaves.
  • Answered: the reply is stored, and the reservation is replaced by its real cost.
  • Ambiguous: the request was sent but no reply arrived, because of a timeout, a cancel or a crash. The reservation is kept. The call is never retried automatically, and no other job sends the same clip to the same model with the same prompt while it's unresolved.

Free models reserve $0 and retry freely. Paid calls run one at a time.

Query

POST/jobs/:id/cancel200 Job

Stop a queued or running job. The CV and ffmpeg subprocesses are killed with it. Stages that already finished stay in the cache for the next job. 409 if the job has already finished.

POST/jobs/:id/resume200 Job

Requeue a Partial or Failed job. It picks up where it stopped: finished stages and answered calls are reused.

Body
{ retryAmbiguous?: boolean }. It authorizes resending only the attempts that are ambiguous right now. The permission is used once, and is cleared on recovery or when the stage finishes.

GET/jobs/:id/result200 JobResult

The highlights, in video time. Each one points back to the segment and the LLM attempt that produced it, so you can audit it.

  "highlights": [

      "class": "Goal", "half": null, "videoSeconds": 175.52, "confidence": 0.95,
      "segmentId": "cab825c8…:5", "attemptId": "09aa3d27-90f8-4278-8f2b-533ee2533b2d",
      "clipUrl": "/blobs/2cb5a2de9c40b10659b8613dc09fb3973280660bb1edbfba5fc808036a59d338" }
  ],
  "coverage": { "segments": 9, "valid": 6, "invalid": 3, "ambiguous": 0, "notSent": 0 } }

Classes: Goal, Shot on target, Shot off target, Foul and Offside, the same five as the thesis benchmark.

GET/blobs/:hash200 bytes

Content-addressed files: highlight clips as video/mp4 and stage artifacts as application/json. It supports Range requests, so a <video> tag can seek.

GET/budget200 Budget

Account-wide paid spend. The ambiguous amount is money that may or may not have been charged.

{ "limitUsd": 0.8, "committedUsd": 0.516, "reservedUsd": 0, "ambiguousUsd": 0 }

GET/jobs/:id/evaluation · /evaluation/model-rate?model=200

Used by the evaluation tools. The first returns the windows the rule kept, { windows: [{ start, end }] }, for computing the recall ceiling. The second returns the highest recorded cost per video second for a model, { usdPerSecond }, which is null before the model's first call.

Errors

Errors are JSON with a _tag. They're the same tagged errors the generated TypeScript client decodes.

StatusTagWhen
400BadRequestThe input is invalid: a missing file, media that can't be probed, a bad SoccerNet path, or pagination out of range.
404NotFoundNo such source, job or blob.
409ConflictThe state doesn't allow this transition, for example resuming a running job, or the source changed during registration.
500PersistenceErrorA real server fault.
 
{ "_tag": "NotFound", "resource": "job", "id": "nope" }
{ "_tag": "BadRequest", "operation": "listJobs",
  "message": "offset must be nonnegative and limit between 1 and 100" }

A failed job carries its own error in state.error, with its stage and a category: SourceChanged, Inference, Process, Provider, Persistence or InvalidInput.

Schemas

The source of truth is Effect Schema in packages/contracts. The server, the CLI and any future web UI import the same definitions, and the HTTP client is generated from them.

TypeShape
Source{ id, ref: SourceRef, mediaHash, probe: { duration, fps, size, frameCount } }
Job{ id, sourceId, spec, state, stages[], coverage, committedUsd, reservedUsd, createdAt, updatedAt }
JobStateQueued | Running{stage,done,total} | Succeeded{coverage} | Partial{coverage,reason} | Failed{stage,error} | Cancelled

Coverage{ segments, valid, invalid, ambiguous, notSent }

Measured results

End to end on three held-out SoccerNet halves, with flash-lite as the model and 40/5 segments, scored against Labels-v2 at a 5 s tolerance.

0.39
F1@5s across 3 held-out halves (precision 0.30, recall 0.57)
88%
of labeled events kept by the rule filter (the recall ceiling)
$0.07
LLM cost per 45-minute half, with google/gemini-3.1-flash-lite
~5 min
of CV per 224p half on CUDA (95 s scene cuts, 204 s detection)

Three halves are enough to show the system works end to end. They're too few to quote as a stable score. Most errors are false positives, and "Shot on target" alone causes over half of them. On the same 100 benchmark segments, GLM 5.3 Flash scored F1 0.31 against flash-lite's 0.56, so flash-lite is the paid model.
